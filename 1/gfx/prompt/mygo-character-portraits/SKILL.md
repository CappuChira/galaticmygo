# MyGO Character Portraits

为《星际迷子：永恒归还》制作统一、可复用、可追溯的人物立绘。把角色身份还原放在第一位，把项目服装语言放在第二位，把科幻装饰放在第三位。

本流程负责人物素材生产和验收，不自动修改事件脚本、portrait 定义或 WIP 资源 key。只有通过验收的衍生图才进入 `1/gfx/` 正式路径。

## 固定输入

开始角色批次前读取：

- 角色提示词：`1/gfx/prompt/<character-id>.txt`，例如 `../anon.txt`。
- 至少一张可靠的原作角色参考，用于脸型、发型、瞳色、体型和标志性配饰。
- 已批准的 MyGO 项目立绘，用作画风、服装密度、线条与上色参考。首批制作尚无批准样张时，把结果标记为“风格基准候选”，不要假装风格已经固定。
- 格式参考：`1/gfx/参考图/格式参考/`。只学习画布、透明底、人物占比、头顶留白和底边截断方式，不复制参考角色的身份或服装。
- 具体用途：透明半身游戏立绘、领袖头像、通讯/事件人物图，或其中若干项。

不要用剧情截图、复杂多人合照、带大面积舞台灯光的宣传图作为唯一身份参考。需要从多人图取样时，只裁出目标角色。

## 输出契约

- 每次生成只包含一个角色、一个主要姿态和一套服装；不同姿态或服装分开生成。
- 生成源图应尽量完整包含头发、披风、双手和主要服装结构，给后续半身裁切保留选择空间。
- 使用严格、均匀的纯色抠图背景。默认纯绿 `#00ff00`；不得有地面、阴影、渐变、光斑、纹理或环境反光。
- 保留未经处理的原始生成图，不在源图上直接覆盖抠图或缩放结果。
- 透明母版使用 PNG RGBA，保持原始可用分辨率和完整人物，不先压成游戏最终尺寸。
- 游戏图必须从透明母版派生；不要把缩小或裁切后的游戏图反向当母版。
- 正式人物图统一输出为 `700x400` PNG RGBA 透明画布。常规人物头顶留白固定为 `70px`；身体、衣摆或披风可在画布底边自然截断。
- 头部和脸部不得贴顶。只有披风、武器或特效等明确越过头顶的构图元素可以进入顶部留白区。
- 人物主体通常落在画布中部略偏左或居中，优先保证脸部、肩部、手势和服装上半身在游戏 UI 中可读。
- 同一角色的脸、发型、瞳色、体型、核心配色和标志性配饰必须跨批次稳定。
- 画面不得包含文字、水印、签名、UI、边框、品牌 logo、其他人物、漂浮道具或独立背景物件。
- 不要用 SVG、PIL、canvas 或其他脚本从零绘制人物。脚本只可用于抠图、裁切、缩放、格式转换、拼接 QA 图和记录元数据。

现有 `1/gfx/anon0.png` 是 `1086x1448` RGB 全身生成源，`1/gfx/anon.png` 是旧的 `700x394` RGBA 半身中间稿。正式 Anon 纹理位于 `1/gfx/portraits/characters/anon.png`，按格式参考重排为 `700x400` RGBA。

## 项目视觉语言

- 日系商业游戏角色立绘，干净动画线稿，动画平涂加少量柔和渐变。
- 保持 BanG Dream! / MyGO 角色的可辨识身份，不把角色重设计成陌生的泛用二次元人物。
- 服装语言为“军装骨架 + 偶像礼服节奏 + 轻科幻功能层”。优先使用清楚的领口、肩部、腰线、裙摆或外套层级。
- 科幻感来自局部半透明材料、低亮度全息饰件、通讯/音乐装置和克制的发光边线，不来自厚重机甲、枪械或高密度机械零件。
- 五名核心角色应共享同一舰队制服家族，但保留各自的主色、性格姿态、轮廓和音乐身份。
- “同一制服家族”只约束材质、制作年代、线稿、上色与少量共同识别件，不要求相同版型。不同角色不得只做换色、换脸或替换胸针。
- 轮廓优先。缩小后仍应先读出角色，再读出服装，最后才读到装饰。
- 光线使用柔和棚拍式主光和轻微轮廓光；肤色、白色布料和浅色头发不得被背景染色。

避免：写实皮肤、强 PBR 金属、高反射塑料、复杂装甲、赛博朋克霓虹、密集粒子、过度透明布料、夸张胸腰比例、幼态化、Q 版、厚涂海报感、复杂透视和喧宾夺主的舞台特效。

## 跨角色服装差异化

生成新角色前读取 `references/character-design-matrix.md`，并与已经批准的角色逐项比较。以下六项中至少四项必须显著不同：

- 外轮廓：长披风、短披肩、无披风、茧型外套、短夹克等。
- 领口与肩部：高领、围巾领、翻领、露肩层、肩章或无肩章。
- 袖型与手部：手套、宽袖、紧袖、非对称袖、手持装置及主要姿态。
- 腰部与下装：礼服腰封、工具腰带、分层裙摆、短外套或实验服结构。
- 配色重心：不得仅替换一种点缀色；明暗比例与大色块位置也要改变。
- 职能与音乐隐喻：指挥、科研、军需、内政、独立勘探及各自乐器/声部应形成不同结构。

不得连续批准使用相同肩章、相同白披肩、相同深蓝胸甲、相同腰带和相同向外伸手姿态的角色。若缩成纯黑剪影后仍像同一人物换色，直接退回重做。

AI 国家元首不必继承 MyGO 舰队制服家族。保留相近的商业动画渲染质量、轻科幻时代感和技术规格，但可以建立独立的国家材质、色彩、权力符号与轮廓体系。AI 元首必须先说明其国家政体和战略气质，再与五名核心角色至少五项显著不同。

## 角色身份锁定

在改服装前先写出一个简短“身份锁定块”，至少包含：

- 角色名、作品名和角色 ID。
- 发色、发长、刘海、分缝、发饰和头发轮廓。
- 瞳色、脸型、年龄感和体型。
- 最不能改变的两到四个辨识点。
- 本批允许变化的内容，例如服装、手持物、姿态和表情。

角色参考负责“她是谁”，项目批准样张负责“这套 mod 怎么画”。不要让服装参考覆盖角色身份，也不要让原作制服限制项目的星际改装。

## 工作目录与版本

角色提示词继续放在 `1/gfx/prompt/<character-id>.txt`。生成批次使用以下结构；目录可在第一次实际生产时创建：

```text
1/gfx/work/portraits/<character-id>/<YYYYMMDD-vNN>/
├── source/       # 原始纯绿背景生成图
├── cutout/       # 透明母版候选
├── qa/           # 黑/白/棋盘格检查图和裁切预览
├── approved/     # 本批批准结果
└── batch-notes.md
```

文件名使用 ASCII 小写字母、数字和下划线：

```text
<character-id>_<batch>_<take>_source.png
<character-id>_<batch>_<take>_master.png
<character-id>_portrait.png
<character-id>_event.png
```

在用户或美术负责人批准前，不覆盖 `1/gfx/` 中已经被脚本引用的文件。

正式纹理放在：

```text
1/gfx/portraits/characters/<character-id>.png
```

portrait 定义放在 `1/gfx/portraits/portraits/00_mygo_portraits.txt`；事件图 sprite 定义放在 `1/interface/00_mygo_event_pictures.gfx`。两处 `texturefile` 都使用游戏内相对路径：

```text
gfx/portraits/characters/<character-id>.png
```

## 工作流

1. 读取角色提示词和本工作流；检查角色 ID、用途、参考图和目标文件是否明确。
2. 从角色提示词提取身份锁定、情绪、姿态、服装、配色、构图、背景与负面约束。缺项时根据角色和现有项目语言做保守补全，并在批次记录中写明。
3. 裁出最少量、最高信息密度的参考图：通常一张身份图加一张项目风格图。不要把混杂的九宫格、文字说明页或无关角色一起传入生成器。
4. 读取 `references/character-design-matrix.md`，先确定新角色与已批准角色在轮廓、领肩、袖型、腰部、配色和职能隐喻上的差异。
5. 按 `references/prompt-template.md` 组装单张提示词。通用规范与角色差异分开写，避免在每个角色文件中复制并逐渐漂移。
6. 先生成少量候选。每次只改变一个主要变量，例如姿态、表情或外套结构，以便知道结果为何变好或变坏。
7. 先做身份筛选，再做美术筛选，最后做技术筛选。身份不对的图即使漂亮也淘汰。
8. 连续几次都无法稳定角色身份时，停止扩写提示词；减少参考图、降低服装改造幅度，或先生成头肩身份基准，再回到全身立绘。
9. 只把通过初筛的源图放入 `cutout/`。移除纯绿背景并做边缘去色，保留发丝、半透明披风、白色衣料和细小配饰。
10. 用 `scripts/prepare_portrait.cjs` 把透明母版排入 `700x400` 画布。默认头顶 `70px`、底边 `0px`、水平中心 `350px`；只有格式参考或 UI 实测支持时才改变参数。
11. 从正式尺寸候选制作黑底、白底和棋盘格 QA 图；同时检查目标 UI 中的实际缩放与遮挡。
12. 通过验收后，把批准母版和衍生图复制到 `approved/`。只有在确认游戏用途和文件名后，才更新 `1/gfx/` 正式资产及相关定义。
13. 在游戏中检查至少一个领袖头像场景和一个通讯/事件场景。根据实际遮挡和缩放调整衍生裁切，不回头破坏透明母版。
14. 在 `batch-notes.md` 记录参考图、使用的提示词版本、批准 take、已知缺陷、目标路径和游戏内验证状态。

运行排版脚本时使用 Codex bundled Node.js 与 `sharp`：

```powershell
$deps = 'C:\Users\LemueDuck\.cache\codex-runtimes\codex-primary-runtime\dependencies'
$env:NODE_PATH = "$deps\node\node_modules"
& "$deps\node\bin\node.exe" `
  '1\gfx\prompt\mygo-character-portraits\scripts\prepare_portrait.cjs' `
  --input '1\gfx\anon.png' `
  --output '1\gfx\portraits\characters\anon.png' `
  --width 700 --height 400 --top 70 --bottom 0 --centerX 350
```

## 选择与淘汰

按以下顺序执行硬门槛：

1. **身份**：一眼可认出目标角色；发型、瞳色、脸型和年龄感正确。
2. **解剖**：双手、手指、手臂、腿部、五官和服装连接自然；没有多肢、融合、断裂或左右错位。
3. **构图**：头部与脸部完整，头顶保留呼吸区；身体在底边自然截断，手势与重要服装结构不被无意义切断。
4. **项目一致性**：像同一支游牧舰队中的 MyGO 成员，而不是五套无关手游皮肤。
5. **角色差异**：至少四项服装结构与已批准角色显著不同；黑色剪影不能像简单换色。
6. **层级**：角色识别度高于服装结构，服装结构高于发光装饰。
7. **技术**：背景平整可抠，边缘清楚，没有阴影、环境色和绿色溢色。

直接淘汰：角色身份明显漂移、手部不可修、衣物结构自相矛盾、脸部左右失衡、披风和肢体粘连、纯绿背景不纯、人物被裁切、过度性化、生成文字或 logo。

不要因为某张图“很华丽”就保留。若华丽感损害角色身份、轮廓、UI 可读性或同队一致性，应选择更克制的候选。

## 抠图与衍生图

- 只删除与画布边缘连通的纯绿/近绿背景，避免误删角色内部的绿色饰件或反光。
- 对发丝、白色披风、半透明材质和轮廓光单独检查 alpha；不要用强硬阈值制造锯齿。
- 对绿色边缘做局部去色，但不要把粉发、蓝色服装或肤色边缘漂白。
- 透明母版四周保留安全边距；裁切由用途衍生层处理。
- 正式游戏图固定为 `700x400` 透明半身构图；默认头顶留白 `70px`，人物像素应延伸到画布底边。
- 事件图优先保证脸、上身动作和标志性服装结构可读；领袖头像优先保证脸、发型与肩部轮廓可读。同一张 `700x400` 纹理可在两种场景共用，但必须分别实测。
- 同一母版可以派生多个用途，但如果某用途的构图明显不适配，应重新生成对应姿态，不要无限强裁。

## 提示词规则

- 先写可验证的视觉事实，再写抽象氛围词。
- 使用具体姿态和镜头描述，不堆叠“高质量、最佳画质”等同义词。
- 角色权重语法属于生成器适配层；只有所用工具支持时才保留 `(角色:1.5)` 一类写法。
- 负面约束集中放在末尾，避免正负描述互相冲突。
- “官方动画风格一致性”必须拆成可检查的线条、上色、比例和身份要求，不能单独依赖这句话。
- 对跨角色批次只改变身份块、角色配色、性格姿态和个性配件；共享画风、制服家族、光线、背景和技术约束。

## 交付检查清单

- 已保留原始纯绿背景源图。
- 已保留最高分辨率透明母版，且没有被 `700x400` 最终裁切覆盖。
- 正式纹理恰好是 `700x400` PNG RGBA，四角透明，头顶保留 `70px`。
- 黑底、白底、棋盘格三种背景下无绿边、白边、黑边或破碎 alpha。
- 发丝、手指、披风、半透明层和鞋底完整。
- 角色身份、服装家族、配色和表情符合本批设定。
- 目标 UI 裁切中脸部清楚，头部不贴顶，重要动作没有被界面遮挡。
- 正式文件名、texture 路径和角色 ID 一致。
- `batch-notes.md` 记录批准版本与游戏内验证状态。
- 修改正式 mod 文件后运行 `1/tools/validate_mygo_mod.ps1`；涉及本地化时另行确认 UTF-8 BOM。
